# 校园食堂智能服务系统

《商务智能》课程大作业项目。

本项目以校园食堂为应用场景，围绕学生就餐、食堂经营管理、学校后勤决策三个层面，构建了一个集描述性分析、预测性分析、规范性分析于一体的校园食堂智能服务系统。系统采用 `Python + React` 的分层架构：Python 负责数据清洗、分析建模、推荐与预测、异常识别、策略模拟和报告数据导出；React 负责前端可视化展示和多角色交互。

与传统“只做几个图表”的课程作业不同，本项目强调完整的商务智能闭环：

`数据采集与清洗 -> 数据质量检测 -> 描述性分析 -> 预测性分析 -> 规范性建议 -> 前端可视化展示 -> 自动报告生成`

---

## 1. 项目背景

高校食堂每天都会产生大量交易数据、评价数据和服务数据，例如：

- 学生消费记录
- 菜品价格与销量
- 食堂与窗口客流变化
- 不同时段高峰压力
- 学生评分与评论反馈

这些数据天然适合进行商务智能分析。如果仅用于记录，其价值十分有限；但如果通过数据分析、关联规则、聚类、回归预测、预警识别和策略模拟等方法进行挖掘，就可以支撑大量真实业务决策，例如：

- 学生今天吃什么更合适
- 哪些菜品最受欢迎，哪些菜品正在衰退
- 午餐和晚餐高峰集中在什么时段
- 哪些窗口在高峰期压力最大
- 哪些菜品需要增加备餐，哪些存在浪费风险
- 促销活动是否有效
- 多个食堂之间谁的经营效率更高
- 后勤部门是否需要对资源进行重新配置

因此，本项目的核心价值是：把校园食堂从经验式管理升级为数据驱动管理，并同时兼顾学生体验、食堂运营效率与学校后勤治理能力。

## 3. 项目目标

### 3.1 总体目标

构建一个覆盖学生端、管理端、后勤端的校园食堂智能服务系统，实现以下能力：

1. 订单数据清洗与质量检测
2. 多维经营分析
3. 学生个性化推荐与消费服务
4. 菜品销量预测
5. 备餐与促销决策支持
6. 异常预警与风险识别
7. 策略模拟与决策评估
8. 日报、周报、月报自动生成

### 3.2 展示目标

本项目不再使用 Streamlit 多页面系统，而采用 React 构建统一前端界面，提升页面表现力、演示完整度和答辩效果。

### 3.3 成果目标

最终形成：

- 可运行的可视化系统
- 可展示的多角色业务页面
- 可解释的分析与预测结果
- 可落地的经营优化建议
- 可直接写入课程报告的完整内容

## 4. 用户与需求分析

系统面向三类核心用户。

### 4.1 学生端用户需求

学生在日常就餐中的真实痛点主要包括：

- 不知道今天吃什么
- 食堂和窗口太多，选择困难
- 想控制预算但缺少消费反馈
- 想少排队、避开高峰
- 想吃得更健康
- 希望对菜品和服务进行反馈

因此学生端重点设计了以下功能：

- 今日吃什么推荐
- 我的消费报告
- 预算与健康建议
- 菜品评分反馈

### 4.2 食堂管理端用户需求

食堂管理人员更关心日常经营和资源安排，例如：

- 今日营业情况如何
- 哪些菜卖得好，哪些菜卖得差
- 哪些时段最忙，哪些窗口压力大
- 哪些菜适合做促销
- 促销后有没有效果
- 明天应该准备多少份食材和菜品

因此管理端重点设计了以下功能：

- 经营数据看板
- 菜品销售分析
- 消费高峰分析
- 关联规则分析
- 销量预测
- 备餐建议

### 4.3 后勤决策端用户需求

后勤部门更关心跨食堂的整体治理与长期优化，例如：

- 各食堂经营差异如何
- 哪些风险需要优先处理
- 哪些经营策略值得尝试
- 如何快速生成日报、周报和月报

因此后勤端重点设计了以下功能：

- 多食堂对比
- 异常预警中心
- 策略模拟器
- 自动报告生成

## 6. 当前已实现的功能说明

### 6.1 学生端功能

#### 6.1.1 今日吃什么推荐

该模块用于解决学生“选择困难”的问题。学生可以结合以下条件进行筛选：

- 预算
- 时段
- 口味
- 目标
- 食堂偏好

系统基于以下因子生成推荐结果：

- 历史偏好
- 菜品评分
- 菜品热度
- 时段适配度
- 目标匹配度
- 不喜欢菜品惩罚

系统还支持个性化套餐生成，结合关联规则和价格约束输出可直接购买的套餐建议。

#### 6.1.2 我的消费报告

该模块为学生提供个人消费画像，主要包括：

- 累计消费金额
- 平均客单价
- 常去食堂
- 常吃菜品
- 消费时段偏好
- 消费标签

#### 6.1.3 预算与健康建议

该模块从“消费控制”和“健康饮食”两个维度服务学生：

- 月预算跟踪
- 月底消费预测
- 超预算预警
- 高消费菜品提醒
- 营养结构分析
- 健康饮食建议

#### 6.1.4 菜品评分反馈

该模块允许学生进行双向互动：

- 收藏喜欢菜品
- 标记不喜欢菜品
- 对菜品进行评分和评论
- 对上新菜品进行投票

这些反馈数据会进一步反哺管理端和后勤端分析。

### 6.2 管理端功能

#### 6.2.1 经营数据看板

该模块用于快速掌握整体经营概况，展示内容包括：

- 总销售额
- 总订单量
- 消费学生人数
- 各食堂经营对比
- 数据质量评分

#### 6.2.2 菜品销售分析

该模块重点展示菜品层面的经营表现，包括：

- 热门菜品 Top10
- 菜品销量与销售额
- 价格与销量关系
- 菜品生命周期分析

生命周期阶段包括：

- 新品期
- 成长期
- 稳定期
- 衰退期
- 淘汰观察期

#### 6.2.3 消费高峰分析

该模块重点分析不同时段的订单压力，包括：

- 早餐、午餐、晚餐、夜宵分布
- 30 分钟粒度订单趋势
- 星期-小时热力分析
- 窗口压力排行

#### 6.2.4 关联规则分析

该模块基于 `Apriori` 挖掘学生在同一订单中的搭配关系，用于：

- 推荐套餐搭配
- 联动促销建议
- 菜品组合优化

系统输出支持度、置信度、提升度等指标。

#### 6.2.5 销量预测

该模块使用随机森林回归进行销量预测，展示内容包括：

- `MAE`
- `RMSE`
- `R²`
- 真实值与预测值对比
- 未来 7 天预测
- 销量变化最快菜品

此外，本模块已增加“特征重要性解释”，可展示：

- 最重要的具体特征
- 特征组贡献度
- 自动生成的解释结论

#### 6.2.6 备餐建议

该模块根据预测销量和安全系数生成备餐建议，并划分：

- 缺货风险
- 浪费风险
- 正常备餐

同时支持窗口级备餐汇总。

#### 6.2.7 评论关键词分析

该分析能力将学生反馈从结构化评分扩展到文本层面，主要输出：

- 高频好评词
- 高频差评词
- 问题主题归因
- 重点问题菜品
- 评论样本展示

#### 6.2.8 促销效果评估

该分析能力用于复盘促销活动是否有效，主要比较：

- 促销前后销量变化
- 促销前后销售额变化
- 促销前后评分变化
- 效果结论与复盘建议

### 6.3 后勤端功能

#### 6.3.1 多食堂对比

该模块用于横向比较多个食堂的整体经营情况，展示内容包括：

- 各食堂经营规模
- 综合效率排名
- 多食堂销售趋势
- 满意度趋势
- 资源利用指数
- 备餐风险总览
- 学生群体结构
- 食堂品类结构

#### 6.3.2 异常预警中心

该模块可自动识别多类风险问题，包括：

- 满意度下降异常
- 窗口订单异常
- 菜品销量异常
- 备餐风险异常
- 拥挤度异常

并支持按优先级展示高、中、低级异常。

#### 6.3.3 策略模拟器

该模块支持用户输入经营策略参数，并即时模拟结果。当前支持的参数包括：

- 价格调整
- 折扣系数
- 增加人手
- 备餐系数

模拟输出包括：

- 销售额变化
- 订单量变化
- 利润变化
- 学生评分变化
- 平均排队时间变化
- 缺货风险变化
- 浪费风险变化

这一模块非常适合体现“规范性分析”。

#### 6.3.4 自动报告生成

该模块支持一键切换并生成：

- 每日报告
- 每周报告
- 月度报告

报告内容采用更正式的管理视角排版，自动汇总：

- 核心经营指标
- 高优先级异常
- 风险概览
- 优化建议
- 报告正文

## 8. 核心算法与技术方案

### 8.1 数据处理

使用 `Pandas` 完成以下工作：

- 数据读取
- 类型转换
- 时间特征构造
- 缺失值与异常值处理
- 聚合统计

### 8.2 学生推荐

推荐模块采用“规则筛选 + 多因子评分”的方式，综合考虑：

- 历史偏好
- 菜品评分
- 热度水平
- 时段适配
- 目标匹配
- 预算匹配
- 不喜欢惩罚项

### 8.3 关联规则分析

使用 `mlxtend` 中的 `Apriori` 和关联规则算法，核心流程如下：

- 构造购物篮
- One-hot 编码
- 挖掘频繁项集
- 生成关联规则
- 根据支持度、置信度、提升度筛选高价值规则

### 8.4 学生画像与聚类

根据学生消费金额、订单数量、平均客单价、时段偏好、高价菜占比等特征进行聚类，形成不同消费群体标签，例如：

- 价格敏感型
- 早餐依赖型
- 夜宵偏好型
- 高频刚需型

### 8.5 销量预测

项目采用随机森林回归模型预测菜品销量，使用的主要特征包括：

- `lag_1`
- `lag_7`
- `rolling_mean_7`
- `weekday`
- `is_weekend`
- 菜品、类别、食堂、窗口等哑变量

模型评估指标包括：

- `MAE`
- `RMSE`
- `R²`

### 8.6 特征重要性解释

为了增强预测模块的可解释性，系统进一步分析随机森林特征重要性，并从以下维度进行归组：

- 历史销量特征
- 时间特征
- 菜品特征
- 食堂与窗口特征

### 8.7 异常预警

通过滑动时间窗口和阈值规则识别业务异常，包括：

- 评分下降
- 订单量偏离历史均值
- 菜品销量突变
- 备餐风险过高
- 拥挤程度异常

### 8.8 策略模拟

策略模拟器通过规则化业务响应函数，近似评估经营决策变化对以下指标的影响：

- 销量
- 销售额
- 利润
- 排队时间
- 缺货风险
- 浪费风险
- 学生满意度

## 11. 运行方式

### 11.1 导出前端展示数据

在项目根目录执行：

```powershell
python src\export_frontend_data.py
```

该命令会生成前端页面所需数据文件：

`frontend/public/dashboard-data.json`

### 11.2 启动前端

```powershell
cd frontend
npm install
npm run dev
```

默认访问地址通常为：

```text
http://localhost:5173
```

### 11.3 停止运行

在终端中按：

```text
Ctrl + C
```

## 16. 局限与后续优化方向

### 16.1 当前局限

1. 当前数据以样例和模拟数据为主
2. 评论分析目前采用轻量规则法，尚未接入更复杂的中文 NLP
3. 策略模拟器采用可解释规则近似，不是严格因果实验模型
4. 销量预测特征仍可继续扩展天气、考试周、节假日等外部因素

### 16.2 后续优化方向

1. 增加天气、节假日、考试周等扩展特征
2. 增加菜品淘汰与上新推荐
3. 增加用户权限体系与数据库持久化
4. 增加移动端或小程序适配
5. 增加报告导出为 PDF 或 Word 的正式能力
